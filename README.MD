# Online Store — интернет-магазин на Django

Многостраничный интернет-магазин с каталогом товаров, кастомной аутентификацией по email и встроенным блогом. Позволяет продавцам публиковать и редактировать свои товары, покупателям — просматривать каталог по категориям, а администрации — модерировать публикации через права доступа.

## Функционал

**Каталог товаров (`catalog`)**
- Главная страница со списком товаров (`ProductListView`), детальная карточка товара (`ProductDetailView`)
- Просмотр товаров по конкретной категории (`get_products_by_category`)
- CRUD-цикл для товара: создание (`ProductCreateView`), редактирование (`ProductUpdateView`), удаление (`ProductDeleteView`) — доступны только авторизованным пользователям
- Проверка владения: редактировать и удалять товар может только его автор (`product.owner != request.user` → `403 Forbidden`); удаление также доступно модератору с правом `catalog.delete_product`
- Кастомное разрешение `can_unpublish_product`, позволяющее избранным пользователям снимать чужие товары с публикации без права полного удаления
- Валидация формы товара: запрет отрицательной цены и блок-лист стоп-слов (реклама казино, крипты, «бесплатно» и т.п.) для полей названия и описания
- Страница контактов с данными техподдержки и отдела продаж (доступна только авторизованным пользователям)
- Управляющие команды `add_categories` и `add_products` — сбрасывают таблицы и перезагружают тестовые данные из JSON-фикстур
- Кеширование в Redis: список товаров на главной и результаты фильтрации по категории кешируются на 15 минут, детальная страница товара кешируется через `cache_page`; кеш включается флагом `CACHE_ENABLED` в `.env`

**Пользователи (`users`)**
- Кастомная модель пользователя `CustomUser` (наследник `AbstractUser`) с входом по email вместо username, плюс поля телефона, страны и аватара
- Собственный `CustomUserManager` с корректной обработкой `create_user`/`create_superuser` для email-аутентификации
- Регистрация, вход и выход через `CreateView`/`LoginView`/`LogoutView` Django
- Приветственное письмо на email при регистрации (`send_mail` сразу после создания пользователя)

**Блог (`blog`)**
- Список опубликованных постов на главной странице блога (`is_publicated=True`)
- Полный CRUD для постов: создание, редактирование, детальный просмотр, удаление
- Счётчик просмотров поста, увеличивающийся при каждом открытии детальной страницы

## Архитектура и технические решения

- **Три Django-приложения** со чёткой зоной ответственности: `catalog` — витрина и товары, `users` — аутентификация, `blog` — контент-блог. Общая точка связи — `Product.owner` ссылается на `users.CustomUser`.
- **Модели и связи**: `Product` связан с `Category` через `ForeignKey` (`on_delete=SET_NULL`, чтобы удаление категории не роняло товары) и с `CustomUser` через `ForeignKey owner` по той же схеме. `Contacts` — независимый справочник контактов компании. `BlogEntry` не связан с другими моделями и хранит счётчик просмотров прямо в записи.
- **Кастомная модель пользователя**: `AUTH_USER_MODEL = 'users.CustomUser'` задан с самого начала проекта — `username` отключён, `email` сделан уникальным полем входа (`USERNAME_FIELD = "email"`), что потребовало написать собственный менеджер модели для `createsuperuser` и программного создания пользователей.
- **Class-Based Views**: весь функционал построен на generic-классах Django (`ListView`, `DetailView`, `CreateView`, `UpdateView`, `DeleteView`) вместо функциональных вью — это сокращает шаблонный код и даёт единообразный CRUD во всех трёх приложениях.
- **Права доступа и авторизация**: `LoginRequiredMixin` закрывает страницы каталога от неавторизованных пользователей; проверка владения товаром сделана вручную через переопределение `get()` (`HttpResponseForbidden`, если пользователь не автор); для операции снятия с публикации используется декоратор `@permission_required` с кастомным Django-permission, объявленным в `Meta.permissions` модели `Product`.
- **Кеширование**: подключён Redis как backend `django.core.cache` (`CACHES` в `settings.py`). Кеш применяется точечно — на список товаров, отфильтрованный список по категории и детальную страницу товара — и полностью управляется через переменную окружения `CACHE_ENABLED`, что удобно для локальной разработки без Redis.
- **Данные для разработки**: тестовые категории и товары хранятся в JSON-фикстурах (`catalog/fixtures/`) и накатываются management-командами, которые сначала очищают таблицу, а потом вызывают `loaddata` — удобно для быстрого сброса состояния БД при разработке.
- **Email-уведомления**: письмо о регистрации отправляется синхронно через `django.core.mail.send_mail` сразу после сохранения формы регистрации; все SMTP-параметры вынесены в `.env`.
- **Файлы и медиа**: изображения товаров, блога и аватары пользователей хранятся в `MEDIA_ROOT`, отдаются в дев-режиме через `static()` в `config/urls.py`.

## Стек технологий

- `Python 3.12`
- `Django 6.0`
- `PostgreSQL` + `psycopg2-binary` — основная БД
- `Redis` — кеш-бэкенд Django
- `Pillow` — обработка загружаемых изображений
- `python-dotenv` — переменные окружения
- `Bootstrap 5` + `Bootstrap Icons` — вёрстка интерфейса
- `Poetry` — управление зависимостями

## Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/MrProdeon/DjangoProject.git
   cd DjangoProjectFirst
   ```

2. Установите зависимости через Poetry:
   ```bash
   poetry install
   ```

3. Создайте файл `.env` на основе `.env.template` и заполните переменные:
   ```
   # Секретный ключ Django
   SECRET_KEY=

   # Включение Redis-кеша (True/False)
   CACHE_ENABLED=

   # Подключение к PostgreSQL
   NAME=
   USER=
   DB_PASSWORD=
   HOST=
   PORT=

   # SMTP для отправки писем
   EMAIL_BACKEND=
   EMAIL_HOST=
   EMAIL_PORT=
   EMAIL_USE_TLS=
   EMAIL_USE_SSL=
   EMAIL_HOST_USER=
   EMAIL_HOST_PASSWORD=
   DEFAULT_FROM_EMAIL=
   ```

4. Поднимите PostgreSQL и (опционально, для кеша) Redis, укажите их адреса в `.env`.

5. Примените миграции:
   ```bash
   poetry run python manage.py migrate
   ```

6. (Опционально) заполните каталог тестовыми данными из фикстур:
   ```bash
   poetry run python manage.py add_categories
   poetry run python manage.py add_products
   ```

7. Создайте суперпользователя для доступа в админку:
   ```bash
   poetry run python manage.py createsuperuser
   ```

8. Запустите сервер разработки:
   ```bash
   poetry run python manage.py runserver
   ```

| URL | Приложение | Описание |
|---|---|---|
| `/` | catalog | Главная страница каталога |
| `/contacts/` | catalog | Контакты (только для авторизованных) |
| `/product/<pk>/` | catalog | Детальная страница товара |
| `/add_product/` | catalog | Создание товара |
| `/update_product/<pk>/` | catalog | Редактирование товара |
| `/delete_product/<pk>/` | catalog | Удаление товара |
| `/product_by_category/<pk>/` | catalog | Товары выбранной категории |
| `/blogs/` | blog | Список опубликованных постов |
| `/blogs/detail/<pk>/` | blog | Детальная страница поста |
| `/users/register/` | users | Регистрация |
| `/users/login/` | users | Вход |
| `/users/logout/` | users | Выход |
| `/admin/` | — | Django-админка |
